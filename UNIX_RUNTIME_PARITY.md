# WinUAE Unix Runtime Parity Audit

This audit compares the current Unix CMake target against the Windows build surface in `od-win32/sysconfig.h`, `od-win32/winuae_msvc15/winuae_msvc.vcxproj`, the Unix feature flags in `od-unix/sysconfig.h`, the Unix CMake source list, and the remaining host stubs in `od-unix/stubs.cpp`.

Status values:

- **Enabled**: linked and backed by a Unix implementation.
- **Partial**: linked, but incomplete or not yet validated against Windows behavior.
- **Stubbed**: build symbols exist, but the Unix implementation returns no-op/empty results.
- **Deferred**: Windows supports it, but the Unix build intentionally does not enable it yet.
- **Windows-only**: not planned as a direct port; needs a native Unix equivalent or UI hiding.

## Highest-Risk Gaps

1. RTG/Picasso96 is visible in the UI and partially active, with guest-driver smoke coverage for Z2/Z3 startup, a non-default 800x600x8 screen open, constrained 16-bit mode-list exposure, and direct 640x480x15 / 640x480x16 / 640x480x24 / 640x480x32 Picasso96API screen opens. Hardware sprites/overlays, multi-monitor RTG placement, render threading, and hardware RTG boards are explicitly disabled or neutral-saved until implemented.
2. A2065/SLIRP and SANA-II `uaenet.device` are compiled by default with startup/autoconfig smoke coverage, but guest-driver networking, pcap/tap/tun, and `bsdsocket.library` are not yet validated/enabled as a coherent networking story. The unsupported networking checkboxes/board families remain disabled.
3. Audio output exists through SDL3, but Windows has many more audio/MIDI/board paths. Native MIDI, sampler input, and sound-board families are disabled or neutral-saved until Unix backends exist.
4. Host integration stubs are still broad: capture, printer/parallel, CHD/7z/RAR archive variants, native media passthrough, CPU boards, and hardware graphics boards are intentionally disabled or neutral-saved in the Qt UI. Clipboard sharing covers text and SDL `image/bmp`/ILBM, but still needs fuller host image MIME support. Joystick/gamepad support has a first SDL3 backend and Qt remap/test UI, but still needs real-device validation and live `uae_prefs` runtime wiring.
5. The main user-visible partial features left enabled are `PICASSO96`/`uaegfx.card`, A2065/SLIRP, SANA-II `uaenet.device`, selected image-backed SCSI/IDE expansion controllers, and SDL3 input/audio/video. Those are backed and smoke-covered, but not yet Windows-equivalent.
