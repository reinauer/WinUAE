# WinUAE Unix Runtime Parity Audit

This audit compares the current Unix CMake target against the Windows build surface in `od-win32/sysconfig.h`, `od-win32/winuae_msvc15/winuae_msvc.vcxproj`, the Unix feature flags in `od-unix/sysconfig.h`, the Unix CMake source list, and the remaining host stubs in `od-unix/stubs.cpp`.

Status values:

- **Enabled**: linked and backed by a Unix implementation.
- **Partial**: linked, but incomplete or not yet validated against Windows behavior.
- **Stubbed**: build symbols exist, but the Unix implementation returns no-op/empty results.
- **Deferred**: Windows supports it, but the Unix build intentionally does not enable it yet.
- **Windows-only**: not planned as a direct port; needs a native Unix equivalent or UI hiding.

## Highest-Risk Gaps

1. RTG/Picasso96 is visible in the UI and active for the currently backed paths, with guest-driver smoke coverage for Z2/Z3 startup, a non-default 800x600x8 screen open, constrained 16-bit mode-list exposure, and direct 640x480x15 / 640x480x16 / 640x480x24 / 640x480x32 Picasso96API screen opens. Hardware sprite exposure now defaults on like Windows, vblank is preference-gated, RTG render threading and SDL RTG backbuffer queueing are wired, and hardware RTG/PCI/PCem/QEMU VGA board source sets are built by default. Remaining risk is guest-software validation, overlay behavior, full multi-RTG placement, Metal/Vulkan shader backends, and board-specific ROM/driver validation.
2. A2065/SLIRP, pcap/tap/tun, SANA-II `uaenet.device`, and `bsdsocket.library` are compiled by default with startup/autoconfig smoke coverage where practical, but guest-driver networking still needs real setup validation.
3. Audio output exists through SDL3, sampler input has a first SDL3 recording backend, native MIDI input/output/routing is backed through CoreMIDI/ALSA when available, and the shared Toccata/Prelude/UAESND sound-board family now builds with Toccata autoconfig smoke coverage. Windows still has more audio/MIDI paths; MIDI volume, DSP/Munt, and PCI sound devices remain deferred until native backends exist.
4. Host integration stubs are still broad: RAR archive extraction, direct hardware parallel I/O beyond Linux `ppdev`, Metal/Vulkan shader backends, hardware graphics board guest/ROM validation, QEMU-PPC guest validation, and broader host capture codec integration beyond the internal DIB/PCM/WAV codecs are still implementation tasks. CHD and 7z are now linked, but real-image validation and compatible FLAC packaging remain. Native hard-drive enumeration has a first read-only Unix backend, native CD is backed on macOS/Linux, macOS SCSITaskLib and Linux SG_IO SCSI/tape passthrough are linked through the SPTI slot, non-PPC CPU-board support is linked through the shared core, the QEMU 11.0 plugin builds from the sibling tree, and ARM64/x86_64 JIT is enabled on wired Unix hosts. Clipboard sharing covers text, SDL `image/bmp`/ILBM, PNG image MIME when libpng is available, and macOS TIFF through ImageIO, but still needs fuller Linux host image MIME support. Joystick/gamepad support has a first SDL3 backend and Qt remap/test UI, but still needs real-device validation and live `uae_prefs` runtime wiring.
5. The main user-visible partial features left enabled are `PICASSO96`/`uaegfx.card`, A2065/SLIRP/pcap/tap/tun, SANA-II `uaenet.device`, selected image-backed SCSI/IDE expansion controllers, native media backends, non-PPC CPU boards, Toccata/Prelude/UAESND sound boards, Unix JIT, and SDL3 input/audio/video. Those are backed and smoke-covered at least at startup/autoconfig level where host hardware is not required, but not yet Windows-equivalent.
